--------------------------------------------------------------------------------
0. THE "WHY" & HISTORICAL CONTEXT (Dev & DevOps Perspectives)
--------------------------------------------------------------------------------
* History: Git was created in 2005 by Linus Torvalds out of frustration with existing
  proprietary tools (BitKeeper) and older centralized version control bottlenecks.
  
* CVC (Centralized Version Control) vs DVC (Distributed Version Control):
  - CVC (SVN, CVS, Perforce): Single central server holds history. If the server is 
    down, you cannot commit locally, review full history, or work offline.
  - DVC (Git, Mercurial): Every developer has a complete copy of the repository 
    and its history. Commits are local, incredibly fast, and resilient to server failures.

* Why use Git?
  - For Developers: Provides a safe sandbox (branching) to experiment without breaking 
    the stable main code. Allows instant time-travel/reverts to fix mistakes.
  - For DevOps: Acts as the "Single Source of Truth." Everything—including infrastructure 
    as code (Terraform), Kubernetes manifests, and CI/CD pipelines—lives in Git. It provides 
    auditability, reproducibility, and automated triggers for deployments (GitOps).

--------------------------------------------------------------------------------
1. SETUP & INITIALIZATION
--------------------------------------------------------------------------------
git init
    Initialize a brand new, empty local Git repository in the current directory.

git clone <url>
    Download/copy an existing repository from a remote host (GitHub, GitLab, Bitbucket).

git config --global user.name "Your Name"
    Set your identity name globally for all repositories on your system.

git config --global user.email "your.email@example.com"
    Set your identity email globally. Essential for attributing authorship in commits.

--------------------------------------------------------------------------------
2. BASIC WORKING COMPASS (Your Daily Commands)
--------------------------------------------------------------------------------
git status
    See the state of your working directory (tracked/untracked changes, staged files).

git add <filename>
    Move specific file changes from the working directory to the Staging Area (the Index).

git add .
    Stage all modified and new files in the current folder and subfolders.

git commit -m "Commit message"
    Take a permanent snapshot of staged files in your local repository history.

git log
    Show the chronological list of commits in the current branch.

git log --oneline --graph --decorate
    A cleaner, visual ASCII graph of your commit history and branch paths.

--------------------------------------------------------------------------------
3. REMOTE SYNCHRONIZATION
--------------------------------------------------------------------------------
git remote add origin <url>
    Link your local repository to a remote server URL under the shortname 'origin'.

git remote -v
    List all configured remote repositories and their URLs.

git push -u origin <branch-name>
    Upload local branch commits to the remote repository and track the branch (-u).

git push
    Push commits to the tracked upstream remote branch (after using -u once).

git fetch
    Download latest references, tags, and history from the remote WITHOUT modifying your files.

git pull
    Fetch from the remote and immediately merge it into your active local branch.
    (Effectively: git fetch + git merge)

--------------------------------------------------------------------------------
4. BRANCHING & MERGING (Parallel Working Universes)
--------------------------------------------------------------------------------
git branch
    List all local branches. The current active branch has an asterisk (*).

git branch <branch-name>
    Create a new branch pointer at your current commit snapshot.

git checkout <branch-name>
    Switch your active working directory to the specified branch.

git checkout -b <branch-name>
    Shortcut: Create a new branch and switch to it immediately.

git switch <branch-name>
    Modern alternative to 'checkout' specifically for changing branches.

git merge <branch-name>
    Combine history from the specified branch into your current active branch.

git branch -d <branch-name>
    Delete a local branch (safely checks if it has been merged).

--------------------------------------------------------------------------------
5. ADVANCED & DEVOPS POWER COMMANDS
--------------------------------------------------------------------------------
git stash
    Save your modified, tracked files into a temporary holding area and revert back 
    to a clean working copy. Great for switching branches mid-work without committing junk.

git stash pop
    Bring your stashed changes back out and re-apply them to your working directory.

git rebase <branch-name>
    Move or combine a sequence of commits to a new base commit. Keeps a linear, 
    clean git log history compared to a messy merge commit network.

git cherry-pick <commit-hash>
    Apply the exact change introduced by an existing commit from another branch into your 
    current branch. Highly useful in DevOps for porting specific hotfixes across environments.

git revert <commit-hash>
    Create a completely new commit that introduces the exact opposite changes of the 
    specified bad commit. Safest way to undo changes already pushed to production.

git reset --soft <commit-hash>
    Move your branch pointer backward in time, but keep your changes staged in the index.

git reset --hard <commit-hash>
    CRITICAL WARNING: Move your branch pointer backward and COMPLETELY wipe out all local 
    working directory changes to match that commit. Uncommitted work will be permanently lost.

git reflog
    The ultimate safety net. Records every movement of HEAD (commits, checkouts, resets). 
    Use this to recover "lost" commits or broken resets.

git bisect start / git bisect bad / git bisect good
    Use binary search to find the exact commit that introduced a bug or broke a pipeline build.

--------------------------------------------------------------------------------
6. DEVOPS INTEGRATION SUMMARY
--------------------------------------------------------------------------------
In DevOps, Git isn't just for code storage; it acts as an automated workflow engine:
1. Webhooks: Git repositories trigger CI/CD pipelines (Jenkins, GitHub Actions, GitLab CI) 
   automatically on 'git push' or Pull Request creation.
2. GitOps: Tools like ArgoCD or Flux continuously monitor Git repositories containing 
   Kubernetes declarations and automatically reconcile the cluster state to match Git.
3. Pull/Merge Requests: Code review gates where automated tests, vulnerability scanners, 
   and peer approvals must pass before code can reach production.
